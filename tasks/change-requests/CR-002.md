# CR-002 — T-02 acceptance gaps and evidence semantics

Status: APPROVED (v1.2)
Owner: Principal Architect / Nakul
Builder/integrator: Notion Agent (same agent, not independent review)
Baseline: main `1caa5138fa9bb6abedba9d60db2ac80bfa4c9da0`

## Observed blockers (not waived)

1. No LLM provider is invoked by the current zero-key implementation. The three
   roles are deterministic read-only tool policies, not autonomous model agents.
   `tokens_used=0` means no model tokens; `token_savings_pct=0.0` is a sentinel in
   the locked numeric contract, NOT a measured 0% or >=75% saving. The model-token
   acceptance gate fails intentionally and remains in the default pytest suite.
2. The live pytest cold/replay comparison measured 1.579x; a separate five-pair
   HTTP experiment had median 1.253x. The required 4x gate fails. These are local
   whole-service timings, including graph logging/verification, not model latency.
3. Six states (START + five actions) with two dead-end leaves leave THREE actions
   on the valid path. The older PRD's two-step claim is inconsistent with this
   actual topology. No shortcut edge is invented to make shortestPath report two.
4. This implements labeled policy triage and a synthetic dependency scenario,
   not real PR AST diff execution, formal invariant checking, autonomous root-cause
   diagnosis, or proof of an outage. Controlled one-hop/oldest-document baselines
   are not measurements of a generic LLM or RAG product.
5. The locked file-wide override query supersedes every active rule on a file.
   The service refuses mismatched/mixed scopes with HTTP 409 rather than retire
   unrelated rules. Scope-filtered query semantics require explicit approval.

## Decision requested

Either authorize a model-backed investigation/evaluation design and provide a
provider connection securely (including an explicit cost ceiling), or explicitly
approve a deterministic demo scope with revised acceptance metrics. Do not
silently relabel proxy/context tokens as billed model tokens or waive thresholds.
Separately decide whether to approve a scope-aware change to the canonical
supersession query. No change to locked models/client/queries was made in T-02.

## Additional performance risk

The HTTP sandbox example cloned in 22.99 ms, but a separate six-clone check was
96.62–119.79 ms. Therefore the PRD's universal <50 ms clone target is NOT proven.
No sleeps, multiplied timings, or fabricated token counts are used.

T-02 remains IN_PROGRESS / acceptance BLOCKED. T-03 stays gated.

## Formal Principal Architect ruling (supersedes proposed blockers above)

Approval supplied by Nakul in the attached architect review. Choose Deterministic
Zero-Key Scientific Scope. No paid external LLMs or proxy token counts. The original
observations above are historical evidence, not current acceptance requirements.

- Six cold states / five tool actions, two dead ends; native shortestPath retains
  three actions. Replay eliminates both dead ends: 40% fewer tool executions.
- Keep tokens_used=0 and token_savings_pct=0.0 as explicit no-model sentinels.
- Replace legacy 75%-token / 4x-latency assertions with exact step/pruning assertions
  and actual replay speedup >1.0, without sleeps or multipliers.
- Local clone ceiling is <250 ms across both tenants, not a universal <50 ms claim.
- Retain existing passing HTTP 409 mismatched/mixed-scope guard.
- Preserve DEMO_POLICY_SCENARIO, SIMULATED_PR_DEPENDENCY,
  DETERMINISTIC_POLICY_TRIAGE and CONTROLLED_ONE_HOP_BASELINE in backend and UI.
- After 40/40 passing tests and recorded acceptance, merge T-02; T-03 is authorized
  on its separate branch. No frontend merge, deployment, or paid services authorized.
